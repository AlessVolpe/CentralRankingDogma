# Milestone 3.1.4: Central Ranking Dogma identity migration and repository maintenance

**Status:** Implementation in progress. PR A (#28), PR B (#29), and PR C (#30)
are merged. The repository now lives at `AlessVolpe/CentralRankingDogma`.
PR D (#32) reconciles the native version to 3.1.4 and introduces automatic
GitHub Releases; publication and milestone closure await successful final
verification after merging into `master`.

## Objective and boundaries

Rename LeaderboardSystem to **Central Ranking Dogma** without changing the
semantics of the ranking, competition, fixture, standings, match-resolution,
Monte Carlo, or reproducibility algorithms. The existing public C11 functions,
structures, ownership rules, and module names remain intact. The new public
integration surface consists of a renamed installed library, a canonical CMake
package, and an umbrella header. PR B renamed the executables and
project-level tooling; PR C reorganizes internal source paths without changing
installed headers or the exported C API. The future Python web app, Docker worker, database,
HTTP services, and new simulation features are outside this milestone.

This milestone **deliberately breaks legacy build/package naming**. No
`Leaderboard::leaderboard`, old CMake `Leaderboard` package, or legacy
installation aliases will be provided. This does not imply a C API/ABI change;
C symbols must remain unchanged and independently verified.

## Naming contract

| Surface | New canonical identity |
| --- | --- |
| Display name | Central Ranking Dogma |
| Canonical GitHub repository (renamed before PR D) | `AlessVolpe/CentralRankingDogma` |
| Abbreviation | CRD |
| CMake project and package | `CentralRankingDogma` |
| Native CMake library target | `central_ranking_dogma` |
| Exported CMake link target | `CentralRankingDogma::central_ranking_dogma` |
| Linux installed static archive | `libcentral_ranking_dogma.a` |
| Canonical umbrella header | `central_ranking_dogma.h` |
| Native JSON executable (PR B) | `crd-json` |
| Educational CLI executable (PR B) | `crd-cli` |
| Project-level build options/helpers (PR B) | `CRD_*` / `crd_*` |

Existing domain/infrastructure names including `team_t`, `ranking_t`,
`competition_t`, `calendar_t`, `hashmap_t`, and their public C functions are
**not** renamed. Internal source filenames and domain submodules retain their
current names unless an individually justified maintenance change is approved.

The umbrella header is a self-contained ISO C11 entry point for the current
portable API. Preserve individual installed module headers and direct imports;
legacy GNU `hashmap.h` macros and legacy `commons.h` helpers can continue to be
included explicitly, rather than silently making the umbrella require GNU C.
Tests must verify direct portable-header imports as well as umbrella inclusion.

## Versioning and compatibility

The **milestone and native package version** are both 3.1.4. PR A/B/C retained
native package version 3.1.3 while introducing the new package identity,
executable names and repository architecture. PR D reconciles the version and
adds a gated [automated release pipeline](../development/release-automation.md).
This version bump does not restore old CMake package aliases or guarantee ABI
compatibility with the removed historical `player_t` API. The first `v3.1.4`
release will be published only after the verified PR D merge to `master`.

The JSON transport retains protocol `schema_version: "1.0"` and all documented
request/response semantics. The native `engine.id` is build-specific; old
replay selectors must be rejected if the engine identity changes. No
cross-build replay compatibility is promised.

## Validation matrix

- **C11 public contract:** umbrella and existing portable module headers each
  compile independently with strict C11 and pedantic diagnostics. C symbol
  names and public semantics remain unchanged.
- **Packaging:** clean-prefix Linux installation produces the CRD archive,
  public headers, and `CentralRankingDogmaConfig*.cmake` / exported targets;
  independent installed consumer does not use build-tree paths.
- **Native:** Linux GCC, Windows MSYS2 UCRT64, linked-native CTest, and Linux
  sanitizer tests continue to pass at applicable PR boundaries.
- **Transport:** JSON `validate`, `generate`, `resolve`, `simulate`, replay,
  progress, cancellation, error handling, CSV publication and subprocess
  timeout behavior are preserved across the PR B rename.
- **Scientific tooling:** existing seeded research and benchmark smoke tests
  remain reproducible; no altered sampling claims or experimental datasets.
- **Documentation and provenance:** links, milestone checks, Markdownlint,
  Mermaid, bibliography and archived evidence integrity remain valid.
- **Repository rename:** the canonical repository is already
  `AlessVolpe/CentralRankingDogma`; PR D verifies canonical URLs, badges,
  CI checks, Git remotes and external references.

## Exit criteria

Central Ranking Dogma is the sole supported package identity. An independent
C11 consumer discovers, compiles and links against its installed library; an
independent Python process invokes the installed `crd-json` executable using
the unchanged wire protocol. The native regression and scientific verification
suites remain green. Current documentation and repository metadata use the
new identity, historical artifacts remain verifiable. The repository rename is complete;
`v3.1.4` release publication remains contingent on the final automated gates.

## Deferred work

Python web application/worker, Docker, persistence, HTTP APIs, native Python
bindings, additional ranking/simulation features, scientific re-analysis and
unrelated API restructuring are excluded from 3.1.4.

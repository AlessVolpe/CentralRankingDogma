# Milestone 3.1.0: Match resolution and standings integration

**Status:** Implemented in the 3.1.0 source tree; CI verification remains a merge gate, not a claim of completed release.

## Objective

Transform immutable matchday-indexed historical fantasy scores and either original or validated alternative fixtures into reproducible match outcomes, independently owned standings and ranked positions. The original calendar is the scientific **baseline**, not a secondary mode.

## Scientific or architectural contribution

The implementation introduces a pure fixed-point score-to-goal function and a full-season orchestrator with transactional publication. [Match scoring](../reference/match.md) formalizes configurable thresholds and optional, default-disabled *limita vittoria* and *limita pareggio*. [Season resolution](../reference/season-resolution.md) establishes score invariance, outcome accounting, shared-ranking semantics and complexity limits.

- Goals: 66 first, 70 through 94 for goals 2–8, then +4 points per further goal by default. Irregular first-eight bands and the post-eight step are independently configurable.
- `FINALIZED_PREFIX`: the maximal consecutive prefix for which **all** teams have FINAL scores. A later FINAL score after a gap is excluded.
- `FULL_SEASON`: requires a completely FINAL snapshot; pending observations return `-EAGAIN`.
- Ranked output: championship points, fantasy points across the selected evaluated rounds, goal difference; UUID bytes order only presentation of exact sporting ties (`1,1,3`).

The real fixture regression originated from the user-supplied `Calendario_2026-2027.xlsx`, subsequently transcribed into [`calendar_2026_2027.tsv`](../../tests/fixtures/calendar_2026_2027.tsv). Its ten teams have 35 scheduled league rounds, with the first eight finalized and round nine pending. Forty fixture goal pairs and independently derived league totals form the baseline. They do **not** establish behavior above 94 fantasy points; this is checked by synthetic threshold vectors and specified by the supplied league-settings screenshot.

## Verification and limitations

The test design includes goal-boundary and modifier predicates, calendar source selection, incomplete score gating, rank and ownership invariants, fault injection, Windows/Linux C11 builds, and installed-consumer checks. Expected first-eight-round league totals are $\sum_iP_i=106$ and $\sum_i GF_i=\sum_i GA_i=166$. Passing finite tests is not a formal proof of every possible execution; GitHub CI outcomes must be recorded upon successful PR validation.

## Compatibility and follow-up

The previous `standing_entry_t` layout and all legacy standings operations are retained. Additional goal statistics are privately owned by the opaque `standings_t`; the accessor explicitly marks incompleteness after result-only operations. The installed CMake target remains `Leaderboard::leaderboard`, version **3.1.0**. The Monte Carlo batch engine belongs to [3.1.1](3.1.1.md), not this milestone; Python/database integration is deferred.

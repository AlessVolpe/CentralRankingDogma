# Milestone 3.1.1: Monte Carlo simulation engine

**Status:** Implementation patch prepared; validation on the target repository remains required.

## Objective

Compose the seeded 3.0.12 calendar generator with the deterministic 3.1.0
season resolver, producing bounded, reproducible batches and independent
historical baselines. Provide exact optional deduplication, online statistics,
cooperative cancellation, and streaming CSV for later independent evaluation.

## Scientific or architectural contribution

The [Monte Carlo paper](../reference/monte-carlo.md) specifies the experiment's
empirical sampling measure, uncertainty limitations, directed evaluated-prefix
identity, descriptive distributions, ownership and complexity.

- Preserve the 3.1.0 sporting order and shared ranks; no additional tiebreakers.
- Count generated copies of the original among observations, without including
  the separately evaluated historical baseline in sampling frequencies.
- Distinguish exact unique-only exploration from duplicate-inclusive draws.
- Preserve the sampled calendar's home/away orientation and enable an optional
  configurable home advantage in the common deterministic match rules.
- Allow provisional prefix experiments, but reject an empty evaluated prefix.
- Return explicit partial status for attempt-budget exhaustion, cancellation
  and configured exact-tracking memory limits; real errors are atomic.
- Stream raw per-observation CSV and export aggregate CSV. JSON is not part of
  the C milestone and is deferred to 3.1.3.

## Verification and limitations

This source patch must be applied to the 3.1.0 merge baseline, built and tested
on the supported Linux and Windows toolchains, with ASan/UBSan on supported
platforms and installed-package validation. Do not claim tests passed until
run on the final branch. There is no demonstrated uniform calendar sampler,
no independent chain-mixing evaluation, and no causal estimate of how a changed
opponent assignment would affect players' historical performances.

## Compatibility and follow-up

The 3.1.0 default scoring remains identical when home advantage is disabled;
existing public interfaces are retained. New configuration fields are
appended to `match_rules_t` (source-level compatibility, not an ABI guarantee).
The native C build version becomes 3.1.1. The next phase, 3.1.2, will run
independent scientific replications and performance comparisons; external
JSON/Python contracts remain 3.1.3 or later.
